## Задача 1. Журнал только в окне, файл лога — во временной папке

**Что хочет пользователь:** файл `browser-backup.log` не должен создаваться в
папке бэкапа. Журнал остаётся только внутри окна программы. Кнопку
«Открыть файл лога» убрать. Файл лога можно создавать при открытии программы,
но во временных файлах, и удалять при закрытии.

**Где сейчас (проверено по коду):**

| Файл | Строка / что там |
|---|---|
| `log.go` | `Logger` (`SetFile`, `Path`, `Log`, `LogPlain`); файл пишется в `<dir>/browser-backup.log` |
| `gui.go` | строки ~77 `app.w.Bind("openLog", app.jsOpenLog)`; ~91–95 `log.SetSink` + `log.SetFile(app.settings.BackupDir)`; ~259 `jsSetDir` вызывает `log.SetFile(dir)`; ~281 `jsOpenLog` |
| `backup.go` | строка 53 `log.SetFile(backupDir)` — **это и создаёт файл в папке бэкапа** |
| `restore.go` | строка 44 `log.SetFile(backupDir)` — то же |
| `cli.go` | строка 26 `log.SetFile(*dir)` (скрытый `-cli` режим; решить, нужен ли там файл) |
| `ui/index.html` | кнопка `<button ... onclick="openLogFile()" id="t-openlog">Open log file</button>` (~254), i18n-ключ `openlog` (~288 RU, ~EN), `openLogFile()` (~740), `openLog: wrap('openLog')` (~872) |
| `backup_test.go` | строка 25 `t.Cleanup(func(){ log.SetFile("") })` — оставить/поправить под новое поведение |
| `restore_test.go` | строка 15 то же |
| `README.md` | строки 100, 114 — описание лога в папке бэкапа |
| `README.txt` | строки 134–136, 216 — то же |
| `HANDOFF.md` | строка 33 — то же |
| `util.go` | комментарий ~156 упоминает кнопку «Открыть файл лога» |

**План:**
1. `log.SetFile` вызывать один раз при старте с путём во `%TEMP%`
   (например `os.MkdirTemp("", "BrowserBackup-log-")` + файл внутри),
   и удалять этот каталог при выходе — по образцу `removeWebViewData` в `gui.go`.
2. Убрать `log.SetFile(backupDir)` из `backup.go` и `restore.go` (и из `jsSetDir`).
3. Убрать привязку `openLog`, `jsOpenLog`, `log.Path()` (если больше не нужен),
   кнопку в UI, ключ `openlog`, `openLogFile()`, `openLog: wrap('openLog')`.
4. Проверить, что лог в окне (`SetSink` → `window.__log`) продолжает работать
   и что при закрытии временный файл удаляется (Windows держит файл открытым —
   закрывать файл ДО `os.RemoveAll`, как в тестах).
5. Обновить README.md, README.txt, HANDOFF.md: журнал только в окне,
   файл лога — временный и удаляется при выходе.

## Задача 2. Кнопки действий — в своих блоках, а не общие в подвале

**Что хочет пользователь:** сейчас можно отметить и профиль, и бэкап, и тогда
доступны обе кнопки. Нужно разграничить: своя кнопка «Создать бэкап» внизу
блока браузеров, своя «Восстановить» внизу блока бэкапов. Обе изначально
серые и некликабельные, пока ничего не отмечено в своём блоке.

**Где сейчас (проверено по коду):**

| Файл | Что там |
|---|---|
| `ui/index.html` | блок `.foot` (~259–268): `#btn-backup`, `#btn-restore`, `#btn-hint`, `#status`, `#prog` |
| `ui/index.html` | `updateButtons()` (~536): включает `btn-backup` при выбранных профилях, `btn-restore` при выбранных бэкапах, текст подсказки `hintSelProfile` / `hintSelBackup` / `hintBoth` |
| `ui/index.html` | `render()` (~530) вызывает `updateButtons()`; `toggleProf` / `toggleBackup` тоже |
| `ui/index.html` | CSS `.btn:disabled` (~128) — серый вид уже есть; `.foot`, `.foot-row`, `.hint` |
| `ui/index.html` | i18n `backup`, `restoreBtn`, `hintSelProfile`, `hintSelBackup`, `hintBoth` (RU ~320, EN ~364) |
| `ui/index.html` | `applyLang()` (~395) переписывает текст кнопок |

**План:**
1. Перенести `#btn-backup` в подвал карточки «Браузеры и профили»
   (рядом с «Добавить папку…»), `#btn-restore` — в подвал карточки
   «Восстановить из бэкапа».
2. В `.foot` оставить только прогресс и статус (можно убрать `#btn-hint` или
   оставить короткую подсказку).
3. `updateButtons()` не менять по смыслу (уже правильно включает/выключает),
   только убрать ключ `hintBoth` — он больше не нужен, если кнопки разнесены.
4. Проверить, что `render()` после `load()` не теряет обработчики (кнопки
   статические, не перерисовываются — ок).

## Состояние проекта и окружения

* Репозиторий: https://github.com/Hayden-Wright/browser-backup-tool
  * `main` = `95908e6` (первый запуск с выбором папки, кнопки по выбору,
    безопасное восстановление, иконка окна).
  * Релиз `v1.3.0` опубликован, в нём `BrowserBackup.exe` (3 586 560 байт)
    и `README.txt`, собранные из `95908e6`.
* Рабочие копии:
  * `D:\#_Projects\BrowserBackupTool\work` — рабочая копия (Windows).
  * `D:\#_Projects\BrowserBackupTool\verify` — копия для сборки/тестов.
  * WSL `~/bbt` — чистый клон репозитория, из него делается сборка.
* Вспомогательные скрипты в корне проекта: `build.sh` (сборка + тесты из
  чистого клона), `release.sh` (публикация релиза), `check.sh`, `sync.sh`.
* **Go:** на Windows не установлен. В WSL установлен Go 1.26 в `~/go/go/bin`
  (`export PATH="$HOME/go/go/bin:$PATH"`). Сборка Windows-билда:
  `GOOS=windows GOARCH=amd64 go build -ldflags "-s -w -H windowsgui" -o BrowserBackup.exe .`
* **git/gh:** только в WSL (`gh` авторизован как Hayden-Wright).
  Важно: `wsl -d Ubuntu -- bash -lc "git ..."` иногда не находит git —
  надёжнее `wsl -d Ubuntu -- git ...` или запускать скрипт файлом.
* Windows-сторона пишет CRLF, репозиторий — LF. Перед коммитом нормализовать
  (`sed 's/\r$//'`), иначе диф раздувается в разы.
* После правок: собрать, прогнать `go test .` (GOOS=linux), проверить в окне,
  закоммитить в `main`, запушить и выпустить новый релиз (v1.4.0).
